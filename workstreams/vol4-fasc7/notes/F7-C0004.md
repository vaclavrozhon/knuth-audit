# F7-C0004 — Answer29 omits the terminal cyclic index rotation

Confirmed, medium. Independently accepted by the coordinator on7November2026. Source: first digital
Fascicle7, answer29, first paragraph on p163/file178. The full original page is
visible in `images/file-178.png`; the preceding invariant is on that same page.
The incorrect identification can assign a positive rank to an invalid matrix;
that effect motivates medium severity. This concerns array arguments and cells, not
the validity of dynamic programming or weighted unranking.

After choosing a terminal count, the answer identifies `(x0,x1,...,xn)` with
`(a_(m−2)(n−1),a_(m−1)0,...,a_(m−1)(n−1))`. AlgorithmQ does not leave its
cyclic buffer in that order. Immediately before the final update
`(i,j)=(m−1,n−1)`, its oldest slot is
`q=(n−m) mod(n+1)`. The update replaces that slot by the last matrix entry,
so the oldest remaining slot is `s=(n−m+1) mod(n+1)`. The correct identification
therefore uses `(x_s,x_(s+1),...,x_n,x0,...,x_(s−1))` on the left. Usuallys≠0;
in particular, s=1 for the8×8 problem of the exercise.

There is a direct2×2 binary counterexample using the actual histoscape relation,
without changing the problem to an arbitrary relation. Initially every count
is1, and the only update isq=0:

`c_final(d,b,c) = sum_a [r(a,b,c,d)]`.

For binary heights the only invalid2×2 histoscapes have their two1s on opposite
corners. Hence `c_final(0,0,1)=2`: both `[[0,0],[1,0]]` and `[[1,0],[1,0]]`
are valid. The printed identification instead says this count fixes
`(a01,a10,a11)=(0,0,1)`. That specification has only one completion,
`[[0,0],[0,1]]`; its other possible completion is the invalid identity matrix
`[[1,0],[0,1]]`. The stated count interpretation is therefore2 versus1, even
in the smallest nontrivial intended dimensionsm=n=t=2. No asymptotic or
degenerate-dimension convention is involved.

Renaming the counts `c_j` in any convenient enumeration order does not rotate
the named arguments of `c(x0,...,xn)`. An explicit relabeling of the x slots
could repair the prose, but none occurs between AlgorithmQ's invariant and
this identification. The minimal correction is to say that the chosen x
values give the listed final cells **after the corresponding cyclic rotation**,
or write the shifted tuple explicitly.

The current official program supports this distinction. In
`HISTOSCAPE-UNRANK`, “Set up the first partial solution” assigns the most recent
matrix position to `pos[q]`, then decreasesq cyclically while assigning the
earlier positions. Only afterwards does it copy the selected count's digits
to `sol[pos[k]]`. Thus the implementation preserves the required rotation;
it is not a witness of an implementation failure. Source and retrieval hashes:
`sources/histoscape-unrank.w` and `sources/histoscape-programs-manifest.json`.
Official source: https://www-cs-faculty.stanford.edu/~knuth/programs/histoscape-unrank.w
