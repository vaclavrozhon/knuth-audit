# F7-C0015 — Residual supports can read an inactive, uncleared word

Confirmed, medium severity, 12 November 2026. First digital release,
March 2025, ISBN 978-0-13-532824-8. Answer 305, printed 224/file 239,
the paragraph about residual supports, in conjunction with answer 304
on the same page. The original typesetting was inspected directly.

A residual support is a cached word index at which a variable/value pair
previously had a supporting tuple. Answer 305 skips searching the active
words when the cached intersection is nonzero. Algorithm R in answer 304
explicitly leaves a word unchanged when its intersection becomes zero:
it removes the word's index from the active prefix instead. A cached index
can therefore point to a stale nonzero word outside that prefix.

Here is a counterexample for every word width e >= 2. Use two variables
x,y with domains {0,1} and {0,...,e}, and list the permitted tuples as

    tau_i = (0,i)   for 0 <= i < e,
    tau_e = (1,e).

Initially every tuple is valid and every domain value is supported, as
the question requires. The two words representing the table are
b[0] = 2^e-1 and b[1] = 1, with D = [0,1] and S = 2. The support for
x=1 is in word 1, so its cached residual is necessarily 1.

Suppose another constraint removes e from y's domain. The intersection
mask keeps word 0 and clears word 1. Algorithm R takes this exact path:

1. R3 accepts the unchanged first word and increments i from 0 to 1.
2. R3 computes zero for the second word and goes to R4.
3. Since i=j=1, R4 goes directly to R7, which changes S to 1.

It never changes b[1], which is still 1. The sole tuple with x=1 has been
deleted, but the residual shortcut tests b[1] AND r[x,1][1] = 1. It therefore
skips the active-word scan and retains x=1. Domain consistency, the promised
result of the exercise, has not been restored. Taking e=64 gives an ordinary
65-tuple machine-word example; the failure does not require empty domains,
backtracking, or a special initialization. The current singleton-domain
erratum does not help: x's domain still has size 2.

A repair must make the two optimizations agree. Either clear and trail
words when Algorithm R removes them, or validate that a cached word index
is still active before accepting it. The latter requires an inverse position,
a suitable validity mechanism, or an active-prefix lookup; none appears in
the printed shortcut. The ordinary active-word scan is sound. This finding
establishes missed pruning, not by itself a false final solution.

The original Compact-Table paper uses the first approach: Algorithm 1,
lines 22–28, stores the new word even when it is zero, before removing its
index. Consequently its residual lookup in Algorithm 2, lines 23–29, does
not have this defect. See [Demeulenaere et al., arXiv:1604.06641](https://arxiv.org/pdf/1604.06641),
PDF pages 6 and 10. This comparison supports the diagnosis; the direct
counterexample above does not depend on external implementation details.

The official TeX and both rendered PostScript errata lists were refreshed
on 12 November. Their answer-305 entry, dated 13 September 2026, only removes
the restriction SIZE_j>1 from domain filtering. They do not change Algorithm R
or the residual shortcut. See the saved refresh manifest and current-source
reconciliation. Targeted public searches for Knuth/304/305/residual supports
and reversible sparse bitsets found no matching report. Absence from these
sources is not a claim of absolute priority. No message was sent externally.
