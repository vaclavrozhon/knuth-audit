# Publication review: Volume 1, enumeration boundaries and storage

Reviewed 12 November 2026. Original statement, answer and relevant official corrections were read together. Existing general arguments and accepted execution records were reused where sufficient; no large computation was repeated. No matching prior public report was located for these thirteen findings. Neither absolute priority nor later physical printing contents are established.

- **V1-C0058 — retain.** Exercise 16 does not exclude a one-node tree. After the 2005 D1 correction to j<n, n=1 gives C[1]=0. D2 chooses that vertex and D3 reads f(V1), although the word is empty. A return with PARENT[1]=0 before D2 fixes this input. This is separate from the already published D1 correction.
- **V1-C0059 — retain as a minor proof endpoint.** At k=m the construction on p.590 has no last removed leaf and hence no f(V0) to start the cycle. Its asserted m-1-letter word cannot have m distinct final entries. The pure cycles number (m-1)!, exactly the value of the final expression. The omission can be repaired separately and is not an incorrect enumeration; lower the severity to low.
- **V1-C0060 — retain.** Exercise 13 on p.405 allows a single weight and specifies arrays indexed from one. With m=1, H2 selects the extra sentinel and H3 decreases k from 1 to 0, writing outside those arrays before the termination test. Returning after copying the sole weight repairs it. No claim is made against Huffman's method itself.
- **V1-C0061 — retain.** Reread A1–A7 on pp.428–429 and the requested changes on p.606. At end of input L becomes zero. A5 removes all positive-level entries, then its equality branch removes (0,NULL) and reads the now empty stack; the added action also writes SCOPE(NULL). This follows even after granting the intended next address and skipping the unwanted name-table action. The fix must finish positive-level scopes and stop before the sentinel is removed. The defect is not merely the ambiguity of the word “continue”.
- **V1-C0062 — retain for the abstract G9 step.** G9 explicitly performs the copy and then advances using SIZE(P). A two-word live node at 2 moved over a dead word to 1 overwrites the old header at 2 with payload. The subsequent size lookup can advance incorrectly and overwrite live data. Ascending copying protects the copied payload but not the old header. The detailed memory model on p.455 uses fields stored at addresses, so treating the old size as implicitly saved requires an additional operation. The MIX answer already saves it in I5 and has no such defect.
- **V1-C0063 — retain.** Answer 34 explicitly assumes LINK(0) is nonzero. Its lines 50–52 translate a zero field through that value without a null test; one unmoved live two-word node suffices to become self-linked. The abstract G8 explicitly excludes null fields. A J6Z to the loop test before line 51 preserves them.
- **V1-C0064 — retain as a separate timing sum.** Directly summing the printed frequencies gives c contributions 3c,9c,6c,6c, totaling 24c rather than 25c. Here c counts runs of inaccessible nodes. The existing null-free execution examples isolate this discrepancy from C0063. The new null check has its own additional cost and must not be folded into a purported correction of the original formula without explanation.
- **V1-C0065 — retain as a typographical equality error.** On p.617 the alternating sum equals H(2m-1)-H(m-1), but the left side extends to 2m+1. At m=2 the sides are 77/60 and 5/6. Changing the upper endpoint to 2m-1 retains the inequality with log(2) and the final allocation bound.
- **V1-C0066 — retain.** The stated pool is exactly 0,...,M-1 and no sentinel is reserved. A request ending at M uses its last word M-1. Thus the failure test must be AVAIL+N>M, not >=M. The counterexample M=N=1,AVAIL=0 is valid under that explicit layout.
- **V1-C0067 — retain.** In the non-power-of-two pool extension, a buddy starting at P with length 2^k fits at equality P+2^k=M. The p.611 test wrongly treats equality as unavailable. In a six-word pool, freeing 5 then 4 fails to combine the valid pair [4,6). The relevant general argument and reachable state were checked; the correction is a strict inequality.
- **V1-C0068 — retain, published erratum only.** Compared the 2006 changes for abstract R2 and MIX lines 17,18,20 with the original listings. The changed unlinking uses the last endpoint, but I4 is still loaded from the first endpoint in lines 08/14. For head->0->2->head, allocation removes 0 as if it were last and disconnects 2. Loading AVAILB[j] at R2 repairs this and costs 2u. The original 1997 front-removal program and the abstract correction are correct; the incomplete MIX correction is the defect.
- **V1-C0069 — retain as a comment error.** Original line 17 loads P into I5, so line 20 stores through P. Its comment instead says L. The original field should be LINKB(P), or LINKF(P) after the erratum. This is independent of C0068 and does not make the original instruction faulty.
- **V1-C0070 — retain as a minor qualification.** The preceding construction explicitly includes m=2. Its sole row is ones; after the prescribed zero boundaries are added, row 2 is zero, and the basic region has zero ones/twos. The two later universal claims instead require a one and m-3=-1 occurrences. Restrict those auxiliary claims to m>=3. The principal bijection survives; lower severity to low rather than implying a substantive enumeration failure.

## Correction and public-report search

All1-prepre, all1-pre, all1, err1 and err1.textxt were freshly downloaded from the [author's index](https://www-cs-faculty.stanford.edu/~knuth/taocp.html); the relevant layers are unchanged from the archived sources. Searches and readings covered pp.393,397,428–429,443,590,596,599–601,606–607,611–615,617 and the named algorithms. The original 2006 errata displays were inspected directly. Other changes concern D1, a frieze identity, renamed algorithm steps, ROVER, buddy coalescing, and bibliography; none supplies the missing repairs discussed here.

Targeted public queries included `Knuth TAOCP buddy allocation errata 2006 AVAILB`, `Knuth compaction NULL SIZE G9 error`, `Knuth SCOPE end input stack algorithm error`, `Knuth Huffman single weight algorithm H error`, `Knuth AVAILB error`, `Knuth compaction NULL error`, `Knuth frieze empty`, `TAOCP canonical singleton`, `Knuth connected mapping pure cycle canonical representation error`, `Knuth linear decoder canonical tree n=1 error`, `Knuth first fit harmonic 2m+1 error`, and `TAOCP buddy pool boundary exact fit error`. Generic descriptions of the algorithms and returned copies of the book do not establish earlier reports of these particular defects. Search coverage is limited, not an exhaustive novelty proof.
