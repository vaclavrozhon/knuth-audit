# V1-C0002 — The exponentiation algorithm needs b>1

**Confirmed · high severity.** 3rd edition · 1st printing · 1997.

Location: Volume 1 · §1.2.2 · Exercise 28

Algorithm E needs the precondition b > 1. Page 22 permits any positive real base b throughout this section, including bases between 0 and 1; exercise 28 restricts the exponent to [0,1) without narrowing b.

Algorithm E needs the precondition b > 1. Page 22 permits any positive
real base b throughout this section, including bases between 0 and 1;
exercise 28 restricts the exponent to [0,1) without narrowing b.

Apply the corrected initialization from the 2002 and 2011 errata.
Take b=1/2, epsilon=1/4, and original exponent a=1/4. Then the working
x starts at 1-epsilon-a=1/2. The first table entry is log_(1/2)(2)=-1,
exactly representable in binary. E3 does not increment k, because
x < -1 is false. E4 replaces x by x+1. The successive values are
3/2, 5/2, 7/2, ...; k stays 1 and E2 cannot terminate. In a format
restricted to the stated exponent range, the first update overflows.
This argument is independent of rounding in y.

Suggested clarification: begin the proposed solution with "Assume b>1."
The cases b=1 and 0<b<1 can be handled separately, if desired.

Checked against the May 1997 first-printing scan and all1-prepre,
all1-pre, all1, and err1 available on November 1, 2026. The initialization
corrections were applied; no base restriction was located in those
errata. The public account by Sean Werkema (October 14, 2021) concerns
the initialization error, not this missing precondition. No claim of
priority, author acceptance, or physical-copy verification is made.

## Publication review, 12 November 2026

Corrected initialization still fails for a permitted base below one; Werkema reported a different initialization defect.

Decision: `retained`. No matching prior report was found in the checked sources; absolute priority is not established.
