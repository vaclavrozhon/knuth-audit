# V3-C0020 — The inverse tableau algorithm can leave its active rows

**Confirmed · medium severity.** 2nd edition · 1st printing · 1998.

Location: Volume3 / answer to exercise5.1.4–39(f), p.614, AlgorithmQ2–Q3

AlgorithmQ can fail to reconstruct a four-cell input: its only candidate has no path to the current cell, and Q3 cannot reach its stopping point.

Take the valid pair P=[1 2;3 4], Q=[0 −1;1 0]. After two valid inverse steps P=[4 3;1 2]. At target(2,1), the sole candidate is(2,2), but the printed comparison chooses the upper3 over the left1 and moves into row1. Subsequent up/left moves can never return to row2. The candidate tree and Q3 must exclude the upper neighbor when r=i. The primary algorithm has this boundary; all five errata layers were checked.

## Publication review, 12 November 2026

The inverse tableau algorithm on p. 614 must ignore the upper neighbor when r=i, both in defining paths and in Q3. The valid 2 by 2 input in the detailed note reaches (i,j)=(2,1), then leaves the remaining region. Novelli, Pak and Stoyanovskii's original algorithm explicitly imposes the corresponding boundary.

Decision: `retained`. No matching prior report was found in the checked sources; absolute priority is not established.
