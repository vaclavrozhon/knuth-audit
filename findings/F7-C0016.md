# F7-C0016 — The initial support scan reads past ITEM when every item is primary

**Confirmed · medium severity.** Published fascicle · Digital release 1 · 2025.

Location: Fascicle 7, answer 341, Algorithm A step A6, printed 232/file 247

Bound the loop before reading ITEM[k], or use the primary-item count as the official companion implementation does. Ordinary exact-cover inputs are affected.

A6 advances and reads ITEM[k] before checking any item-count bound. With primary p,q, options {p},{q}, and no secondary items, its first support scan reads the uninitialized ITEM[2].

## Publication review, 12 November 2026

Algorithm A, step A6, reads ITEM[k] after incrementing k without testing the array end. The ordinary nonempty exact-cover instance with two primary items and no secondary items reaches the uninitialized ITEM[ACTIVE]. The official xccdc program uses a bounded scan and is correct at this point.

Decision: `retained`. No matching prior report was found in the checked sources; absolute priority is not established.
