# V2-C0109 — The division-free conversion can output an invalid decimal digit

**Confirmed · medium severity.** 3rd edition · 1st printing · 1997.

Location: Volume 2 · §4.4 · Exercise 8

The printed MIX program fails for the ordinary input u=10. Two corrections are required.

The constant1//10 is rounded down, so the first quotient for u=10 is zero and the remainder becomes10. Replacing it by an upper approximation alone is insufficient: ADD U still uses the original input on every iteration. Save the current input before each outer loop and use floor(w/10)+1 with the existing quotient repair. The archived instruction-level checks and general error bound support both corrections.

## Publication review, 12 November 2026

The original MIXAL // operator truncates. Thus MUL =1//10= uses a lower reciprocal and input 10 produces the invalid digit 10. Raising the reciprocal alone still leaves ADD U using the original input on later iterations, producing 0,10. Saving the current quotient before each reciprocal multiplication repairs this second defect. Both faults follow directly from the original listing; the existing exact simulator checks of the combined correction are retained.

Decision: `retained`. No matching prior report was found in the checked sources; absolute priority is not established.
