# V2-C0251 — FADD loses the sticky tail when its fraction overflows

**Confirmed · medium severity.** 3rd edition · 1st printing · 1997.

Location: Volume 2 · Section 4.2.1 · Program A, N4 · Printed page 219

Valid normalized operands produce an incorrectly rounded sum. Preserve whether the old X was nonzero when inserting the carry in N4.

With base 100, u = +50|99 99 99 50 and v = +48|50 00 00 01, the exact sum is 1.000049500001. The program returns 1.000049 although 1.000050 is closer. N4 replaces a nonzero X by 1, then shifts it to zero; N5 mistakes a value above the midpoint for an exact tie. The error remains after the 2002 correction.

## Publication review, 12 November 2026

N4's ENTX 1 on p. 219 discards the nonzero trailing register. With radix 100 and the two recorded normalized inputs, the exact sum 1.000049500001 is nearer 1.000050, but the original and 2002-corrected programs return 1.000049. The instruction trace and exact neighbor distances were rechecked; the known opposite-sign correction does not touch N4. Preserve whether old X was nonzero. This does not transfer the old timing bound to modified code.

Decision: `retained`. No matching prior report was found in the checked sources; absolute priority is not established.
