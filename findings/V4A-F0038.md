# V4A-F0038 — Swapping omits the new child reference increments

**Confirmed · medium severity.** 1st edition · 1st printing · 2011.

Location: 4A / Answers7.1.4-147 and202, printed648 and660: new-node reference counts during swapping

A later garbage collection can reclaim a reachable node. U3 must increment both child counts in this variant.

The swap variant changes U1 and U2 but leaves U3 without increments for the new node children. A three-variable example finishes with a reachable node at REF=0.

## Publication review, 12 November 2026

Answers 147 and 202, pp. 648 and 660: the swap modifications decrement references when old nodes disappear but do not increment the children when U3 creates new nodes. The small witnesses in the detailed note leave a reachable child with reference count zero. This concerns the printed modifications; Knuth's public bdd14 program already increments both children.

Decision: `retained`. No matching prior report was found in the checked sources; absolute priority is not established.
