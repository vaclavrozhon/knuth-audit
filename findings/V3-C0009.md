# V3-C0009 — Distribution counting writes outside its table when u=v

**Confirmed · medium severity.** 2nd edition · 1st printing · 1998.

Location: Volume 3 / answer 5.2-9, p. 616

A valid one-key range can corrupt a neighboring input record.

For M=v−u=0, the accumulation loop still executes once and writes COUNT[v+1]. With COUNT=INPUT=100 and two records +1,+2 at addresses 101,102, both keys are zero but the first satellite changes from 1 to 3. The regions do not overlap. Skip this loop when M=0. The abstract algorithm is correct; the error is in its MIX implementation. Original typesetting and all relevant errata checked.

## Publication review, 12 November 2026

For the permitted key range u=v, the MIX code on p. 616 enters its accumulation loop with index 1 and accesses COUNT[v+1]. A disjoint but adjacent input area can therefore be modified. This is a defect of the MIX implementation; Algorithm D's bounded accumulation loop is correct.

Decision: `retained`. No matching prior report was found in the checked sources; absolute priority is not established.
