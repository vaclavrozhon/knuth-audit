# C013 — Initialization omits the headers’ COLOR fields

**Confirmed · medium severity.** 1st edition · 2nd printing · 2022.

Location: 4B / P1 and answer 220, p. 110,474

The book reads an unspecified marker; the published C program zeroes it.

The final review of P1 confirms missing initialization of COLOR for primary headers. Page 89 does not explicitly prescribe it, and exercise 220 reads the marker. An explicit three-row input misses a blocking reduction when COLOR(b)=5 but removes it when COLOR(b)=0. The solution set is preserved; the C source uses calloc and does not have this problem. Confirmed in the PDF and PostScript. The original C013 identifier is retained.

## Publication review, 12 November 2026

P1 inherits C1 initialization, and p. 89 explicitly permits uninitialized COLOR fields in primary headers. Answer 220 later reads those fields as option-address marks. The three-row input with primary items a,b and secondary item s, rows `a s:1`, `a`, `b s:2`, skips a blocking test when COLOR(b)=5. Zero initialization fixes it. This is incomplete preprocessing, not loss of solutions; the author's calloc-based program already avoids it.

Decision: `retained`. No matching prior report was found in the checked sources; absolute priority is not established.
