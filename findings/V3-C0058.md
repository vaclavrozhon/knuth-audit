# V3-C0058 — The binary-search loop example uses the wrong endpoint

**Confirmed · low severity.** 2nd edition · 1st printing · 1998.

Location: Answer 6.2.1-2(a,c), printed 705: loop example uses K>K_u instead of K>K_l

The supporting loop example falls outside the exercise's present-key premise; a one-subscript correction supplies a valid witness. The yes/no result is unchanged.

The exercise promises that K is present, so K>K_u cannot hold in its current search interval. With two keys and K=K_2, l=u-1 and K>K_l leave the modified lower endpoint unchanged forever.

## Publication review, 12 November 2026

On p. 705 the explanation for variants (a,c) needs K>K_l, not K>K_u. The exercise assumes K is present, so the latter condition is impossible in the maintained interval. For two keys and K=K_2, midpoint 1 and the modified assignment l=1 repeat forever. The answer's yes/no classification is correct; its supporting witness is outside the promised domain.

Decision: `retained`. No matching prior report was found in the checked sources; absolute priority is not established.
