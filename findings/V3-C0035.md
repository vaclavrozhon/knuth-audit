# V3-C0035 — The multiway-merge comparison bound rounds down instead of up

**Confirmed · low severity.** 2nd edition · 1st printing · 1998.

Location: Answer 5.2.4-1, printed 646 / file 657.

The exact bound should be ceil(lg k). The merging algorithm and logarithmic complexity remain valid.

With five input streams, replacing a deepest winning leaf can require three comparisons; floor(lg 5) is only two.

## Publication review, 12 November 2026

The per-output tournament-merging bound on p. 646 needs ceil(lg k), not floor(lg k), in general. With five streams, replacement of a winner on a deepest leaf leaves four mutually unordered possible winners, requiring three comparisons; floor(lg 5)=2. This concerns the comparison bound, not failure to sort.

Decision: `retained`. No matching prior report was found in the checked sources; absolute priority is not established.
