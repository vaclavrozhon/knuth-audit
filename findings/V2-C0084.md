# V2-C0084 — The one-digit ternary case needs an exception

**Confirmed · low severity.** 3rd edition · 1st printing · 1997.

Location: Volume 2 · §4.2.2 · Exercise 15

The universal claim misses the one-digit ternary case. The usual binary midpoint guarantee is unaffected.

There is an exception to the assertion about bases b > 2, even after
the September 14, 2019 correction: take b = 3, p = 1, with halfway
cases rounded to an even last digit. Algorithm N permits this choice
for odd b. Rounding halfway cases away from zero works here too.

Write R for rounding. Every nonzero floating point number in this
format is +/-3^e or +/-2*3^e. Now

R(R(2*1)/2) = 1,
    R(4) = 3, and R(3/2) = 2,

so R(R(2v)/2) = v for every v, by scaling and sign symmetry.
Monotonicity then gives, for u <= v,

u = R(R(2u)/2) <= R(R(u+v)/2) <= R(R(2v)/2) = v.

Thus the computed midpoint always lies between the endpoints in this
format, provided the operations are defined. The claim for b > 2
needs to except b = 3, p = 1, or specify a different halfway rule
there. With rounding to odd the property does fail: u = v = 2 gives
computed midpoint 1.

I checked the original third-edition printing and all four applicable
errata layers. The 2019 replacement does not address this exception.
A later physical printing has not been checked. Nothing has been sent.

## Publication review, 12 November 2026

The claim for every base greater than two has the exception base 3, precision one, with ties to even or away from zero. Directly rounding twice after doubling and halving returns each representable value; monotonicity then places every computed midpoint between its endpoints. Ties to odd do not have this exception. The 2019 replacement was applied.

Decision: `retained`. No matching prior report was found in the checked sources; absolute priority is not established.
