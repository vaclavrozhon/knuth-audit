# F205 — BIMP resizing omits the stored size-exponent update

**Confirmed · medium severity.** 1st edition · 2nd printing · 2022.

Location: 4B / SAT answer134, printed574/file594: Buddy block size exponent

Set K←k+1 as well as CAP←2^(k+1); otherwise the second resize again requests eight slots for a full eight-entry list.

The capacity is doubled while the stored exponent K retains its old value.

## Publication review, 12 November 2026

SAT134 doubles capacity without updating the stored exponent K. After 4→8, the next request still uses K=2 and requests eight again. Add K←k+1. The archived SAT11 implementation already performs this update.

Decision: `retained`. No matching prior report was found in the checked sources; absolute priority is not established.
