# V1-C0062 — G9 reads a source header after overwriting it

**Confirmed · critical severity.** 3rd edition · 1st printing · 1997.

Location: Volume 1 · Exercise 33 · page 613

Overlapping compaction can corrupt the live data.

A live two-word node at address 2 is moved to address 1 across one dead word. The copy overwrites its old header at 2 with payload. G9 then rereads SIZE(2), advances to the wrong place and can corrupt the compacted result.

Save the node size before moving it. The MIX implementation already does this correctly in I5. The defect is in the abstract G9 step.

The original pages and all four current/historical errata layers were reviewed on November 5, 2026. This does not establish priority or inspection of a later physical printing.

## Publication review, 12 November 2026

Overlapping relocation overwrites the source header before G9 rereads its size.

Decision: `retained`. No matching prior report was found in the checked sources; absolute priority is not established.
