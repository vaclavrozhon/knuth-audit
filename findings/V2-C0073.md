# V2-C0073 — The replacement program uses an undeclared array x

**Confirmed · medium severity.** 3rd edition · 1st printing · 1997.

Location: Volume 2 · §3.6 · Exercise 11

The replacement code starts with the declaration of ss, retaining
these earlier declarations from the first printing:

register int t,s,j;
 double u[KK+KK-1],ul[KK+KK-1];
 double ulp=(1.0/(1L<<30))/(1L<<22);

It then uses x[j], x[j+j], etc., but x is never declared. The separate
instruction changing "copy in ul" to "copy in x" affects the prose,
not the declarations. No other erratum supplies the missing declaration.

The literal reconstruction fails C99 compilation at the first x[j]=0.
Adding

int x[KK+KK-1];

fixes the compilation, and both test runs print
0.36410514377569680455 as specified. The unused ul array can be removed.
Alternatively, remove all auxiliary x operations, as the current
standalone rng-double.c already does. That standalone file is not
claimed to have this compilation defect.

## Publication review, 12 November 2026

The literal 2002 replacement for p. 602 declares the double arrays u and ul but uses an undeclared integer array x. The instruction to rename references inside a loop does not declare x. Adding int x[199] repairs compilation and preserves the two stated test outputs. This is a defect in the printed replacement, not the current standalone rng-double.c.

Decision: `retained`. No matching prior report was found in the checked sources; absolute priority is not established.
