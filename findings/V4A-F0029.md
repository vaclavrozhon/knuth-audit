# V4A-F0029 — The CRC loop skips its second input octabyte

**Confirmed · medium severity.** 1st edition · 1st printing · 2011.

Location: 4A / Answer 7.1.3-213, printed page 620: placement of ADD nn,nn,8 in the CRC loop

The routine can return an incorrect CRC for an ordinary 16-byte message.

After loading the first octabyte the code advances nn by 8, then advances it again before loading the next octabyte. It skips the second input word and eventually reads beyond the input.

## Publication review, 12 November 2026

Answer 213, p. 620: for 16 input bytes the two loads use offsets -16 and 0, skipping -8 and reading past the message. The explicit zero-message-with-final-01 example returns zero instead of the required CRC 0x8005. Moving the loop increment after the load repairs the indexing.

Decision: `retained`. No matching prior report was found in the checked sources; absolute priority is not established.
